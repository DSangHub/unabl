# Video greeting albums

One-time host purchase per event: Classic $7.95 (custom cover/details/dedication, manual page turns) or Gold Embossed $14.95 (gold cover, automatic page turns following video completion, original procedural instrumental music). These are USD album service purchases, separate from gifts, bank-only Knows, and the $1.75 direct-wallet fee. No percentage fee is added to album checkout. Edition is chosen at first save; upgrades are not implemented.

Host: My account → saved event → Create / manage video greeting album. Save cover and edition, preview, purchase via Stripe, refresh status after confirmation, then review/approve/hide/remove guest pages. Guest viewing defaults off; the host can opt into sharing approved pages with confirmed invited guests using the current event access code. Guests find the published event, sign in, enter code, then open the event album and upload. Host can view unapproved uploads; other guests cannot. Guests can view/remove their own uploads. Uploaded original videos do not depend on the unfinished AI voice-animation service.

Limit: 20 active video pages per album, two active uploads per guest, MP4/WebM/MOV, 25 MB each. Reserve quotas are serialized using a server-only invoker RPC. Retry caps: 10 reservations per user/album, 100 per album, including removed slots. Incomplete reservations can be removed by the uploader or host. MIME/size are checked client/server and by the bucket; content is not transcoded or scanned. Codec/browser support varies, especially for MOV; MP4/H.264 is recommended. Longer uploads may need retrying; resumable uploads are not implemented.

Privacy: event_albums, album_orders and album_videos are service-only tables with RLS and no client grants. Private event-greetings bucket has no anonymous/authenticated object policies. The API verifies the current confirmed user, event ownership or invitation+code, and paid live activation before signing upload paths. Browser uploads go directly to Storage using a scoped signed token, not through Vercel body-size limits. Playback URLs expire after five minutes, but anyone possessing one can use it until expiry. Changing guest access doesn't revoke an already-issued URL. Never log URLs/tokens. Removal hides the row first and attempts storage deletion; failed storage cleanup must be retried operationally. Signed upload tokens remain usable until their provider expiry, so removed uploads may need later orphan cleanup. No public album links or automatic email invitations are created. No perpetual retention guarantee or export-to-video is implemented.

Payment: /api/album-checkout charges the host a server-selected price. One pending/paid order per album prevents parallel duplicate purchases, retries reuse Stripe idempotency and open sessions, expired sessions can be replaced. Stripe-hosted checkout uses dynamic payment methods. Checkout return only navigates to My account; activation is exclusively via verified signed webhooks and a matching paid Checkout Session plus a succeeded matching PaymentIntent/latest Charge. Amount, currency, account and environment are checked. Pending async payments do not activate. Sandbox payments never unlock live albums. Refunds/disputes block activation and future access. Terminal order states cannot be resurrected by replayed paid events. Ordinary gift webhook processing is preserved.

Required production webhook subscriptions already used by this project: checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, charge.failed, charge.refunded, charge.dispute.created. The signed platform webhook routes album events before gift Balance/Connect checks; album purchases do not require host Connect onboarding or payouts. Album checkout verifies the Unabl platform account and server key mode; no Balance Read is needed for this separate service purchase. The backend key still needs Checkout Sessions, PaymentIntents and Charges access. No real purchase or user video upload was made during development.

Music is an original synthesized four-chord instrumental bed created in Web Audio, with on/off and pause controls, ducked beneath speech. Starts only after a viewer gesture. Gold does not autoplay audible media on page load; browsers can require a further video Play click. Manual navigation remains available; page animation honors reduced-motion settings. On the final video the slideshow/music stop. Refresh/reopen for expired playback URLs.

Verification: unit suite includes server pricing/validation, guest/code authorization, sandbox isolation, unpaid/mismatched payment rejection, refund/dispute activation blocks, and out-of-order replay protection. Database transaction tests check unique pending purchase and serialized guest quota and roll back fixtures. Live paid checkout → webhook → guest upload still requires an authenticated test purchase; do not claim it passed without performing it.
